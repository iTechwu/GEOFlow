# GEOFlow 深度检查与真实环境验收续报

日期：2026-08-23

## 1. 结论

本轮完成了生产镜像构建、源码构建 Compose、外部 PostgreSQL/Redis、同机 Models、MCP、队列、调度器、Reverb 与 Nginx 的真实运行验收，并修复验收过程中发现的生产级问题。

当前结论为：**应用运行面与 Models 管理面已通过；公共 Models Chat/Embedding 发布门禁仍等待 CI/生产环境提供四项外部配置。** 在这些配置到位前，严格发布脚本会按设计拒绝发布，不应绕过该门禁。

## 2. 本轮发现与修复

| 级别 | 问题 | 影响 | 修复 |
| --- | --- | --- | --- |
| P1 | 生产 worker 未消费 `system-updates` | 系统更新任务永久滞留，但容器仍可显示健康 | 所有生产 worker 与队列监控加入 `system-updates` |
| P1 | Redis `retry_after=360` 小于 600/900 秒长任务超时 | 长任务执行中可能被重复投递 | 默认值提高到 960 秒，并扫描所有 Job 的 timeout 契约 |
| P1 | `composer:2` 内 PHAR 权限及签名损坏 | 默认生产镜像无法构建 | 固定 Composer 2.10.2，并在执行前校验官方 PHAR SHA-256；错误哈希构建会立即失败 |
| P1 | Models 内部接口已返回 `{code,msg,data}`，客户端仍按裸数据解析 | HMAC 鉴权成功但内部管理面门禁失败 | 严格解包当前信封，兼容滚动发布期间的旧裸响应，拒绝业务失败信封 |
| P1 | 生产 overlay 继承开发 `artisan serve` 命令 | Nginx 请求 `app:9000` 得到 502，app 假健康 | prod/prebuilt 显式运行 `php-fpm -F`，健康检查同时验证 PID 1 进程与 FPM 配置 |
| P1 | prod Reverb 端口与基础 Compose 端口列表发生合并 | 同一宿主端口映射到两个容器端口，Reverb 无法启动 | 使用 `ports: !override` 替换开发映射 |
| P1 | prod overlay 继承 `./:/var/www/html`、dev assets 依赖和 app 开发端口 | 生产镜像代码被宿主工作树覆盖，镜像验收产生假阳性 | 五个 PHP 服务使用 `volumes: !override`；app 清除开发端口并替换依赖 |
| P1 | web 健康检查请求业务首页 | 维护模式返回 503，导致“门禁通过前保持维护”无法成立 | 增加 Nginx 专用 `/nginx-health`；Laravel `/up` 仍由发布门禁单独验证 |
| P2 | 状态型调度任务可并发重叠 | 多副本下可能重复清理或重复调度 | 增加 `onOneServer()` 与 `withoutOverlapping()` |
| P2 | Models 内部未知传输异常未留下安全日志 | 故障不可诊断，直接输出异常又可能泄密 | 仅记录固定事件名和异常类，不记录 URL、响应正文或密钥 |

此外，生产迁移与首次安装已改为 init 容器中的显式一次性步骤；app、queue、scheduler、reverb 均强制关闭启动时自动迁移和自动安装。发布健康门禁完成前，Laravel 保持维护模式。

## 3. 真实环境证据

### 3.1 生产镜像

- 完成 `linux/amd64` app 与 web 生产镜像构建。
- 即使基础镜像内 Composer PHAR 损坏，固定 PHAR 校验与替换后，95 个生产依赖仍可完成安装。
- 将 Composer 校验和故意改错时，构建在 Composer 执行前失败。
- 运行容器与生产镜像内 `ModelsInternalClient.php` 的 SHA-256 一致。
- app、queue、scheduler、reverb 仅挂载 `/var/www/html/.env` 与 `/var/www/html/storage`，不再挂载宿主源码。

### 3.2 运行服务

- app：PID 1 为 `php-fpm -F`；

- scheduler：`schedule:work` 正常；

运行配置确认：`retry_after=960`、`AUTO_MIGRATE=false`、`AUTO_INSTALL_ONCE=false`。数据库迁移全部为 `Ran`，首次安装命令识别已有初始化状态并跳过重复 seed。

本地同机 Models 验收仅在未提交的 `.env.prod` 使用精确私网目标白名单和专用本地 HTTP 开关；生产仍应使用 HTTPS。

## 5. 尚未闭环的外部输入

严格健康脚本已验证会在以下缺项处失败：

1. `MODELS_BASE_URL`
2. `MODELS_API_KEY`
3. `MODELS_CHAT_SMOKE_MODEL`
4. `MODELS_EMBEDDING_SMOKE_MODEL`

CI/生产环境补齐后，必须重新执行完整 `geoflow-healthcheck.sh`，以真实 Chat 内容和数值 Embedding 向量作为最终发布证据。不得使用 Models 内部 HMAC 密钥代替公共 `MODELS_API_KEY`。

基础 Composer 镜像仍需从镜像仓库解析元数据；CI 网络受限时应通过 `COMPOSER_IMAGE` 指向企业镜像代理。PHAR 本身仍由固定版本和 SHA-256 验证。

全仓库 Pint 仍有 49 个历史格式问题，均不在本轮变更范围；本轮修改文件已通过格式检查。
