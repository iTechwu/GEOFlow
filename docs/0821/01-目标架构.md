# GEOFlow CI 自动化目标架构

## 目标

CI 机运行 GEOFlow 的网页服务、MCP 服务和后台 Worker。GEOFlow 负责内容、任务、知识库、分发和网页呈现；所有聊天模型与 Embedding 请求统一交给 `models.dofe.ai`，不再在 GEOFlow 容器内维护 Provider 密钥或模型路由。

```text
浏览器 / CI Agent
       | HTTPS
       +--> GEOFlow Web + /mcp
                 | PostgreSQL / Redis（外部）
                 | models.dofe.ai/v1（统一 AI 网关）
                 +--> queue / scheduler / reverb
```

## 边界

- `../docker-helm.dofe.ai` 是 PostgreSQL、Redis、RabbitMQ 的唯一生命周期管理者。本仓库的 Docker Compose 不创建这些服务、镜像、容器或持久卷。
- GEOFlow Web、MCP 和 REST API 共享同一 Laravel 应用与数据库权限边界。
- MCP 是无状态 Streamable HTTP JSON-RPC 适配层，业务规则继续位于现有 Service/API 层。
- `MODELS_BASE_URL` 与 `MODELS_API_KEY` 同时存在时，聊天、Embedding、URL 分析、标题生成、企业知识草稿、后台模型测试和 Worker 统一走 models；旧 `GEOFLOW_AI_*` 仅作兼容回退。

## 部署单元

| 单元 | 作用 | 状态存储 |
| --- | --- | --- |
| `web` / `app` | 公共站点、后台、REST、`POST /mcp` | 外部 PostgreSQL、Redis |
| `queue` | 文章生成、分发、知识库任务 | 外部 Redis + PostgreSQL 任务记录 |
| `scheduler` | Laravel 计划任务 | 外部 Redis + PostgreSQL |
| `reverb` | 后台实时任务状态 | 外部 Redis |
| `models.dofe.ai` | 模型目录、路由、配额、Provider 用量 | models 项目自身 |

## 运行原则

1. 先在集中基础设施中确认数据库、Redis、网络和 DNS 已就绪。
2. 再启动 GEOFlow `init` 完成迁移和安装，成功后启动常驻服务。
3. 最后打开 MCP Token，并用 `initialize`、`tools/list` 和只读工具完成冒烟。
4. 发布失败时回滚 GEOFlow 镜像和代码；不要回滚集中 PostgreSQL/Redis 数据或 models 项目。
