## 已修复问题

### 1. 维护旁路密钥进入 CI 日志

提交：`90d39e7 防止维护旁路密钥写入发布日志`

Laravel 的 `artisan down --secret=...` 默认输出完整旁路地址。发布脚本现在为两处带密钥的调用增加 `--quiet`。隔离容器实测命令退出码为 0、输出为 0 字节，测试标记未出现在日志中。

### 2. Models 运行时可向明文端点发送密钥

提交：`e375f27 阻止模型运行时向明文端点发送密钥`

公共网关探针已经校验 `MODELS_BASE_URL`，但真实 Laravel AI provider 注册入口之前没有复用该策略。现在 Models 统一覆盖在写入 `ai.providers` 前必须通过 `ModelsEndpointPolicy`：

- 生产外部地址必须使用 HTTPS。
- 仅在显式开启本机例外时允许既有的 `dofe-models-api-local` HTTP 地址。
- 校验失败时不写入运行时 provider，也不在异常中包含 API Key。

### 3. 发布失败后持久化旁路密钥未可靠清除

提交：`ed2d995 封存发布失败后的维护旁路密钥`

旧实现只注册 `ERR` trap，并只使用 `compose exec app` 重写维护状态。旧 app 停止后，迁移或门禁失败会导致该命令不可用，`storage/framework/down` 中的临时 secret 可能继续存在。

新实现统一由 `EXIT` 收口，并覆盖 `SIGINT`、`SIGTERM`：

1. 优先在运行中的 app 执行无 secret 的 `artisan down --quiet`。
2. 失败时使用禁止自动迁移和自动安装的一次性 app 容器重写维护状态。
3. 封存失败时输出明确人工处置提示。
4. 清空 shell 中的 `MAINTENANCE_SECRET`，同时保留原失败退出码。

故障注入覆盖普通退出和 `SIGTERM`：分别保持退出码 7 和 143，均执行 one-off 回退，输出不包含测试密钥。

### 4. 带引号的 latest 镜像绕过发布门禁

提交：`e22f423 校验Compose解析后的发布镜像`

旧实现直接使用 `grep/cut` 读取 `.env.prod`。`GEOFLOW_APP_IMAGE="repo/app:latest"` 会保留引号并绕过字符串匹配，而 Compose 实际仍使用 `latest`。

发布脚本现在先执行 Compose 配置解析，再校验 `docker compose config --images` 的最终结果。实测矩阵：

| 输入 | 结果 |
| --- | --- |
| 带引号 `latest` | 拒绝 |
| 不带引号 `latest` | 拒绝 |
| 明确版本标签 | 通过 |
| SHA-256 digest | 通过 |

### 5. 分发任务硬超时后状态可能停在 sending

提交：`60c7309 补充分发任务异常退出回调`

`ProcessArticleDistributionJob` 新增幂等 `failed()` 回调。只有仍处于 `sending` 的记录会通过条件更新转为 `failed`，同时清空 `next_retry_at`、记录截断后的错误信息并写入一次 `distribution.failed` 日志。迟到或重复回调不会覆盖 `synced` 等终态，也不会重复写日志。

## 被排除的假阳性

审查曾推断维护模式下 `/up` 会在旁路 Cookie 生成前返回 503。当前 Laravel 12.64.0 的 `ApplicationBuilder` 在注册 `health: '/up'` 时会自动将该路径加入维护模式例外。

真实生产栈验证结果：

- 进入带随机 secret 的维护模式后，无 Cookie 请求 `/up` 返回 200。
- 携带有效维护 Cookie 请求 `/up` 返回 200。
- 验证结束后 `EXIT` trap 执行 `artisan up`，当前维护模式为 OFF。

因此没有为 `/up` 增加不必要的 Cookie 生成和共享头文件逻辑；MCP 在维护态下仍使用现有的签名 Cookie。
