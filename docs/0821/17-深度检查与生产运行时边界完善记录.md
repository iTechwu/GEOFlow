## 关键问题与修复

### 1. app/web 镜像仍可能来自不同源码

相同 tag 只能证明命名一致，不能证明两个镜像来自同一提交。生产构建现在为 app/web 写入 `org.opencontainers.image.revision`，发布脚本在进入维护模式、停止旧服务之前检查全部已拉取镜像：revision 必须存在且完全相同。校验失败不会影响当前服务。

### 2. CI 凭据残留在 runner

GitHub checkout 的凭据过去会写入工作目录，Docker login 也默认复用 runner 长期配置。现在 checkout 不持久化令牌；镜像构建与部署各自在受控临时目录中使用 Docker 配置，并在成功、失败和取消路径清理。清理前检查目录前缀和符号链接，避免扩大删除范围。

### 3. 构建上下文包含运行时数据

`.dockerignore` 现在排除 `.env*`、`public/uploads`、旧图片目录、`public/build`、`public/hot`、`public/storage` 和 macOS 元数据。真实 BuildKit 上下文导出确认这些路径均未进入镜像构建上下文。

`public/storage` 被排除后，非 root worker 无权在运行时写 `public/`。生产 Dockerfile 因此在构建阶段创建固定的 `/var/www/html/storage/app/public` 链接，运行时无需提升权限重建。

### 4. 生产 APP_KEY 被入口误轮换

CI 渲染器把配置保存为 `APP_KEY='base64:...'`，旧入口只匹配未加引号的文件行 `APP_KEY=base64:`。因此容器每次启动都会误执行 `key:generate --force`，改写宿主 `.env.prod`；当前进程仍使用旧环境变量，下一次部署才读取新值，形成跨发布换钥风险。

修复后：

- CI 和手工部署必须在启动前提供有效的 32 字节 Base64 APP_KEY。
- init、app、queue、scheduler、reverb 在 prod/prebuilt 中全部只读挂载 `.env.prod`。
- 生产入口不再包含 `key:generate`，无效密钥立即失败。
- 后台诊断只提供首次部署密钥生成命令，并要求安全写入 `.env.prod`。

真实生产镜像一次性容器验证：有效密钥可启动，无效密钥被拒绝，容器写 `.env` 被内核拒绝，宿主文件前后 SHA-256 不变。

### 5. 后台常驻进程以 root 运行

旧 queue、scheduler、reverb 的 PID 1 均为 root。生产镜像现在在构建阶段把 `storage` 和 `bootstrap/cache` 交给 `www-data`，两套生产 Compose 对三个后台服务统一设置：

```yaml
user: "www-data"
security_opt:
  - no-new-privileges:true
cap_drop:
  - ALL
```

init 仍以 root 运行，用于修正宿主 bind mount 权限；php-fpm master 仍以 root 启动后切换 worker 到 `www-data`；Nginx master 仍负责启动低权限 worker。本轮没有在缺乏替代启动模型的情况下强行修改这些进程。

独立 amd64 新镜像验收结果：UID 33、`CapEff=0000000000000000`、`NoNewPrivs=1`，`.env` 不可写，storage/cache 可写，`php artisan optimize`、应用启动和 Redis `queue:monitor` 均成功。

## 配置恢复事件

本轮对旧实例执行写权限探针时，命令错误地把宿主 `.env.prod` 截断为探针文本。这是一次验收操作事故，不是应用代码行为。

处置过程：

1. 未重启任何运行容器，利用 app 容器创建时冻结的 `Config.Env` 恢复配置。
2. 从容器环境中减去镜像默认环境，只恢复应用专属项，不打印 Secret。
3. 恢复 86 个应用配置键，文件权限重设为 `0600`。
4. 对恢复文件中的每一项与运行容器做值一致性比较，差异数为 0。
5. APP_KEY 格式检查通过，五个现有容器全过程保持 healthy。

恢复后的文件与当前运行实例语义一致，但原注释、原排序，以及未进入运行容器环境的值无法从冻结环境还原。当前缺失的新 Models/预构建镜像变量应由 CI Secret 重新通过 `render-prod-env.sh` 完整渲染，不能以本次恢复文件作为最终生产 Secret 来源。

## 当前运行差距

当前五个实例创建于本轮修复之前，仍表现为：

- Web/Reverb 端口绑定 `0.0.0.0`，尚未应用 loopback 约束。

这些差距需要发布新 app/web 镜像并按停止、排空、迁移、门禁流程重建服务才能消除。由于严格 Models 门禁尚未通过，本轮没有强行替换健康实例。
