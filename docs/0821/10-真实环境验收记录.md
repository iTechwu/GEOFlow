## 关键发现

### P0：唯一公开 Embedding 模型与网关路由不一致

models 内部目录将 `embedding-vision` 标记为 `text_embedding`、`isAvailable=true`、`isEnabled=true`、`publicationStatus=published`，并声明支持 `embeddings` 协议；但相同模型通过公共 `/v1/embeddings` 调用时返回 400，提示模型类型不支持 embedding 操作。

这会使严格发布门禁 `geoflow:models-gateway-check` 必然失败，也会阻断知识库真实向量化。需要在 models 项目修复模型类型映射或 Provider 路由后，再用同一模型重复公共探针。

### P0：生产数据库缺少 MCP 与租户迁移

以下迁移尚未执行：

- `2026_08_21_000001_create_mcp_audit_logs_table`
- `2026_08_21_000002_add_tenant_to_mcp_audit_logs_table`
- `2026_08_21_000003_add_sso_team_id_to_tasks_table`
- `2026_08_21_000004_add_sso_team_id_to_catalog_tables`

当前 `migrate:status --pending=1` 以非零退出，符合发布健康检查的 fail-closed 设计。迁移应只在维护窗口通过既有 `upgrade` 发布流程执行，不应在验收阶段直接绕过门禁。

### P1：GitHub 生产发布控制面尚未建立

GitHub 仓库当前没有已注册 Runner、Environment、可见 Workflow 或历史 Run。`dev` 分支的工作流与本地提交尚未推送，因此真实 CI 不能开始。创建 `production` Environment、配置 Variables/Secrets、注册带 `geoflow-production` 标签的自托管 Runner 后，才具备端到端发布条件。

### P1：生产环境变量不可注入 PHPUnit 进程

将真实运行环境文件直接作为容器级 env 注入全量 PHPUnit 时，得到 974 passed、35 failed、1 skipped。失败集中表现为：

- 测试动态配置被进程级 models 地址覆盖，模拟请求转为真实网络调用并按 30/60 秒超时；
- 测试共享真实 Redis 限流状态，表单请求返回 429；
- URL 归一化断言被真实公共网关地址覆盖。

移除运行时 env 注入后，同一代码基线全量通过。这不是 35 个代码回归，但说明 CI 的 test job 必须使用隔离的测试配置，生产 `.env.prod` 只能进入 build/deploy 阶段。

### P2：MCP 测试令牌缓存隔离已修复

全文件运行 `McpEndpointTest` 时，两个 SSO 用例复用相同 token，前一用例缓存的团队声明污染后一用例。提交 `a1c01f2` 为无团队用例使用独立 token；生产认证逻辑未改动。修复后 19 项全部通过。
