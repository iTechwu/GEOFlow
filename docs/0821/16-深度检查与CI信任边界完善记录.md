# 深度检查与 CI 信任边界完善记录

日期：2026-08-23

## 审查结论

本轮继续沿真实 CI 发布路径检查 Models 凭据、GitHub Actions 触发条件、预构建镜像配对和生产环境渲染。共确认并修复 4 项可复现问题：

| 优先级 | 问题 | 影响 | 处理 |
| --- | --- | --- | --- |
| P1 | Models 端点策略允许任意 HTTPS 主机 | 可将公共 API key 或内部 HMAC 引向非权威主机 | HTTPS 仅允许 `models.dofe.ai`，本地 HTTP 继续使用显式开关和固定主机 |
| P1 | `workflow_dispatch` 可从任意分支进入镜像构建 | 未合并工作流可读取镜像仓库 Secret 并推送镜像 | 镜像构建和生产发布严格限制到 `main` |
| P1 | 发布门禁未核对 app/web 版本一致性 | 后端代码和前端静态资源可能来自不同提交 | 对 Compose 解析后的全部 tag 执行同版本校验 |
| P1 | 环境生成器原样写入 dotenv | `#`、`$`、空格等字符会改变密码的运行时值 | 统一单引号字面量编码；不兼容的单引号在落盘前拒绝 |

## Models 凭据信任边界

`ModelsEndpointPolicy` 现在同时保护三条凭据发送路径：

1. `ModelsGatewayClient` 的公共 Chat/Embedding API key。
2. `ModelsInternalClient` 的内部 HMAC 请求头。
3. `OpenAiRuntimeProvider` 注册到 Laravel AI 的统一运行时 Provider。

生产 HTTPS 地址必须满足：主机精确为 `models.dofe.ai`，端口为空或 `443`，且 URL 不包含 userinfo、query 或 fragment。`dofe-models-api-local`、`host.docker.internal` 和 `127.0.0.1` 的 HTTP 入口仅在 `GEOFLOW_MODELS_ALLOW_INSECURE_LOCAL=true` 时允许；实际出站仍受私网目标白名单约束。

对应提交：

- `8a5a9fc 限制Models凭据仅发送到权威主机`
- `06a35b8 要求本地Models端点进入私网白名单`

## 发布来源与镜像一致性

GitHub Actions 的 `build-images` 现在要求：

```text
github.ref == refs/heads/main
and event in {push, workflow_dispatch}
```

因此功能分支仍可运行测试，但不能进入读取 Registry Secret 的生产镜像构建。首次空库的 `fresh` 发布必须先把审查后的 revision 合入 `main`，再手工触发。

预构建发布继续拒绝无 tag 和 `latest`。在此基础上，所有非 digest 镜像还必须使用相同版本 tag，CI 当前使用同一个 `github.sha` 生成 app/web tag。校验对象来自 `docker compose config --images`，不会重新手写解析 dotenv。

对应提交：

- `03b4311 阻止前后端镜像版本错配发布`
- `f988d5a 限制生产镜像仅从主分支构建`

## 生产环境值保真

旧生成器写入 `KEY=value`。例如密码 `hash# dollar$ value` 经 dotenv 读取后会被截断或插值，CI 仍会错误地报告生成成功。

新生成器写入 `KEY='value'`，并在原子替换前完成校验。已验证以下字符通过 Laravel dotenv 和真实 Docker Compose 容器后保持原值：

- `#`
- `$`
- 空格
- 反斜杠
- 双引号

Laravel dotenv 不支持与 Compose 一致的单引号内转义，因此包含单引号的输入会按变量名报错，错误信息不包含变量值。目标文件权限保持 `0600`。

对应提交：`20ca44a 防止生产环境凭据在渲染时变形`。

本轮新增行为测试覆盖：

- 非权威 HTTPS Models 主机在发送 key/HMAC 前被拒绝。

- 相同镜像 tag 通过、不同 tag 和 `latest` 失败。

## 尚未闭环

本机未配置真实公共 Models 发布凭据和 smoke 模型，严格公共 Chat/Embedding 门禁仍不能形成生产通过证据。当前本机配置缺少以下值；CI 可使用工作流内置的权威 base URL，但其余项需要在 GitHub `production` Environment 补齐，然后重新执行完整发布：

- `MODELS_BASE_URL`
- `MODELS_API_KEY`
- `MODELS_CHAT_SMOKE_MODEL`
- `MODELS_EMBEDDING_SMOKE_MODEL`
- `MODELS_INTERNAL_API_SECRET`

此外，digest 形式的 app/web 镜像各自不可变，但当前门禁无法仅凭两个不同 digest 证明它们来自同一 Git revision；生产自动流水线使用同 SHA tag，digest 手工发布仍需保留构建证明。
