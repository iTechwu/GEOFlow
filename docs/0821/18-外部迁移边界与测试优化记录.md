# 外部迁移边界与测试优化记录

## 审查结论

GEOFlow 的 PostgreSQL、Redis、RabbitMQ 均由 `../docker-helm.dofe.ai` 管理，应用 Compose 不应保留数据库初始化或迁移服务。原有 `init` 服务虽然使用 GEOFlow 镜像，但会把外部数据库迁移重新绑定到应用编排生命周期，并让常驻服务依赖一次性容器完成。

## 实施结果

- `docker-compose.yml`、`docker-compose.prod.yml`、`docker-compose.prebuilt.yml` 已删除 `init` 服务及相关 `depends_on`。
- 首次安装与已有数据库升级均由部署脚本显式执行 `docker compose run --rm --no-deps app php artisan ...`。
- 开发与生产入口默认 `AUTO_MIGRATE=false`、`AUTO_INIT_ONCE=false`、`AUTO_INSTALL_ONCE=false`；全新本地空库使用 `make dev-init`。
- `check-compose-boundaries.sh` 除外部 PostgreSQL/Redis/RabbitMQ 服务外，也拒绝 `init`、`db-init`、`migrate` 等顶层服务。
- 新增纯 Shell 负向测试，验证普通应用服务可通过，数据库服务和初始化服务会被拒绝；该测试已接入 CI。
- 发布脚本会删除已停止的历史 `geoflow-init-prod` 容器；如果该容器仍在运行则中止发布，避免强制打断迁移。

## 操作边界

全新空库只能在单次外部命令中注入 `GEOFLOW_SECURITY_FRESH_INSTALL_CONFIRMED=true`。已有数据或迁移历史的环境必须先停机并排空旧进程，再仅向迁移命令注入 `GEOFLOW_SECURITY_UPGRADE_DRAIN_CONFIRMED=true`。常驻容器重启不得触发迁移或首次安装。

## 验证范围

- 三种 Compose 文件单独解析和生产 overlay 解析。
- Compose 边界正向与负向测试。
- 发布脚本、环境渲染、运行时契约和 CI 安全测试。
- 完整 PHPUnit、MCP harness、真实 MCP Docker 服务及 models embedding-vision 契约回归。

本机最终结果：PHPUnit `1084 passed`、`1 skipped`、`8457 assertions`；MCP harness `3/3`，五个真实 MCP 镜像全部通过；models 契约与 embedding-vision 定向测试 `64/64`。当前源码生产镜像在 `common_network` 中连接真实外部 PostgreSQL，`migrate:status --pending=1` 返回无待执行迁移，显式 `migrate --force` 返回 `Nothing to migrate`。
