实施已完成主要骨架：模型调用可统一切换到 models，MCP 已具备写/只读令牌、写工具幂等和审计的代码路径，且三个 Compose 文件不再自行创建 PostgreSQL、Redis 或 RabbitMQ。

## 发现

### P1：生产与预构建 Compose 无法连接集中 PostgreSQL/Redis

**证据**

- 目标和运行手册要求使用 `../docker-helm.dofe.ai` 管理的外部基础设施：[01-目标架构.md](01-目标架构.md) 第 18 行、[04-CI部署运行手册.md](04-CI部署运行手册.md) 第 5 行。
- 本机集中编排实际使用外部 Docker 网络 `common_network`，数据库和 Redis 容器名分别是 `dofe-postgres`、`dofe-redis`（`../docker-helm.dofe.ai/docker-compose.yml` 第 28-35、192-245、871 行；本机 `docker network inspect common_network` 也已确认）。
- [docker-compose.prod.yml](../../docker-compose.prod.yml) 第 137-143 行和 [docker-compose.prebuilt.yml](../../docker-compose.prebuilt.yml) 第 96-103 行只创建私有 `geoflow-prod-net`，未声明 `external: true` 的 `common_network`。
- 环境模板和部署脚本却默认使用 `postgres.shared`、`redis.shared`：[.env.prod.example](../../.env.prod.example) 第 106、142 行，[geoflow-docker-deploy.sh](../../deploy-scripts/geoflow-docker-deploy.sh) 第 268-271 行。集中网络中不存在这两个 DNS 别名。
- [entrypoint.prod.sh](../../docker/entrypoint.prod.sh) 第 56-65 行会无限等待 PostgreSQL，因此 `init` 将无法完成，后续服务也无法启动。

**影响**：CI 自动化部署在默认配置下不可用，并会卡住发布流水线。

**建议**：两个生产 Compose 文件将所有 GEOFlow 服务接入 `common_network`（`external: true`，名称参数化），默认主机调整为 `dofe-postgres`/`dofe-redis`，或改为已验证可路由的集中 DNS/VIP；为 `pg_isready` 增加有限重试和明确失败退出。

### P1：MCP 审计日志会持久化未被精确命名的敏感字段和业务正文

**证据**

- `geoflow.tasks.enqueue` 接受可任意嵌套的 `payload`：[McpController.php](../../app/Http/Controllers/McpController.php) 第 72、76-90 行。
- 写操作把完整 arguments 交给审计器：[McpController.php](../../app/Http/Controllers/McpController.php) 第 99-121 行。
- 清洗器只按完全相等的字段名屏蔽 `api_key`、`token`、`password`、`secret`、`authorization`：[McpAuditLogger.php](../../app/Support/McpAuditLogger.php) 第 50-81 行。`apiKey`、`access_token`、`credential`，以及 `payload` 内的 Prompt/正文均会以明文（最多 180 字符）写入 `mcp_audit_logs.details`。
- 这与 [02-models-接入.md](02-models-接入.md) 第 32 行“不记录 API key、完整 Authorization、Prompt 原文”的约束相冲突。

**影响**：数据库备份、审计查询和运维导出会扩大密钥及业务内容的暴露面。

**建议**：审计记录改为白名单字段（工具名、任务 ID、请求 ID、令牌指纹、参数哈希、结果状态），不要保存原始 `payload`；如必须保存参数，采用递归的大小写/分隔符无关敏感键检测，并对正文类字段只保存长度和哈希。

### P2：只读 MCP 令牌未进入环境模板、部署脚本和运行契约

**证据**

- 代码已支持 `GEOFLOW_MCP_READ_TOKEN`，并在写工具处强制写作用域：[geoflow.php](../../config/geoflow.php) 第 109-116 行、[McpController.php](../../app/Http/Controllers/McpController.php) 第 99-113 行。
- `.env.example` 和 `.env.prod.example` 只列出 `GEOFLOW_MCP_TOKEN`：[.env.example](../../.env.example) 第 179-185 行、[.env.prod.example](../../.env.prod.example) 第 183 行之后的 MCP 配置。
- [geoflow-docker-deploy.sh](../../deploy-scripts/geoflow-docker-deploy.sh) 第 275-309 行只读取和写入全量令牌；[03-MCP-契约.md](03-MCP-契约.md) 第 5-9、34-43 行也未说明只读令牌。

**影响**：CI Secret 即便提供只读令牌，一键部署仍会丢失该配置；调用方也无法按读写最小权限接入。

**建议**：将 read token 纳入两个环境模板、部署脚本和 MCP 文档，并添加“仅用于 catalog/list/get”的冒烟示例与轮换说明。

### P2：MCP Feature 测试未覆盖真实写入、安全边界和重试语义

**证据**

- [McpEndpointTest.php](../../tests/Feature/McpEndpointTest.php) 第 18-61 行仅覆盖禁用、缺少令牌、`initialize` 和 `tools/list`。
- 未覆盖只读令牌调用写工具被拒绝、幂等重放/参数冲突、审计写入与脱敏、工具业务异常、未知工具、`task_id` 校验和任务访问边界。
- 运行手册要求验证 MCP 工具调用和任务入队：[04-CI部署运行手册.md](04-CI部署运行手册.md) 第 44-50 行。

**影响**：全自动化最关键的写路径缺少回归保障，令牌、幂等或审计的后续修改可能静默失效。

**建议**：使用真实 SQLite/PostgreSQL 测试库覆盖写工具全链路，并将上述用例纳入 CI；部署阶段在容器内执行 `php artisan test --filter=Mcp`。

### P2：`notifications/initialized` 仍返回 JSON-RPC 响应

**证据**

- [McpController.php](../../app/Http/Controllers/McpController.php) 第 43、145-147 行对 `notifications/initialized` 与 `ping` 同样调用 `result()`；当通知未带 `id` 时会返回 `{ "id": null, "result": ... }`。

**影响**：通知请求不应有响应；严格的 MCP/JSON-RPC 客户端可能将此识别为协议错误。

**建议**：区分无 `id` 的通知并返回 HTTP 204 空响应；保留 `ping` 的正常 JSON-RPC 响应。

### P2：任务所有权策略在 MCP 中尚未显式定义

**证据**

- 现有 API 已按 SSO 所有者保护任务：[TaskLifecycleService.php](../../app/Services/GeoFlow/TaskLifecycleService.php) 第 147-164 行。
- MCP 是部署级无状态令牌，鉴权上下文不携带管理员归属：[McpAuthContext.php](../../app/Http/McpAuthContext.php) 第 6-24 行；MCP 直接调用全局 `listTasks`、`getTask`、`startTask`、`stopTask`、`enqueueTask`：[McpController.php](../../app/Http/Controllers/McpController.php) 第 80-86 行。

**影响**：持有同一 MCP 令牌的任意 CI 任务可读取和改变所有 GEOFlow 任务。若这是部署级运维令牌的预期行为，需要将其明确为权限模型；否则会绕过现有任务隔离。

**建议**：在 MCP 契约中明确“部署管理员全局权限”，并以 IP 白名单、短期令牌和审批策略限制；若需租户隔离，则把服务账号/可操作任务范围放入令牌声明并在 Service 层校验。
