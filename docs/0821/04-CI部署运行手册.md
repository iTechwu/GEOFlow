# CI 机部署运行手册

## 前置条件

- CI 机已加入与 `docker-helm.dofe.ai` 相同的 Docker 网络或可解析 `DB_HOST`、`REDIS_HOST`。
- 外部 PostgreSQL 启用 pgvector（知识库向量检索需要）。
- 外部 Redis 已配置密码、TLS/网络策略和持久化；RabbitMQ 若未来启用也必须由集中基础设施提供。
- models 项目已创建 GEOFlow 公共 API 服务密钥；若启用管理面检查，还需创建内部 HMAC 密钥。

## 环境变量

从 `.env.prod.example` 生成 `.env.prod`，至少填写：

```dotenv
APP_KEY=base64:...
APP_URL=https://geo.example.com
DB_HOST=postgres.shared
DB_PORT=5432
DB_DATABASE=geo_flow
DB_USERNAME=geo_user
DB_PASSWORD=***
REDIS_HOST=redis.shared
REDIS_PORT=6379
REDIS_PASSWORD=***
MODELS_BASE_URL=https://models.dofe.ai/v1
MODELS_API_KEY=***
MODELS_INTERNAL_BASE_URL=https://models.dofe.ai
MODELS_INTERNAL_API_SECRET=***
MODELS_SERVICE_NAME=geoflow
GEOFLOW_MCP_ENABLED=true
GEOFLOW_MCP_TOKEN=***
```

机密通过 CI Secret 注入；不要把 `.env.prod` 放入镜像或构建产物。

## 启动顺序

```bash
docker compose --env-file .env.prod -f docker-compose.prod.yml build
docker compose --env-file .env.prod -f docker-compose.prod.yml run --rm init
docker compose --env-file .env.prod -f docker-compose.prod.yml up -d app web queue scheduler reverb
docker compose --env-file .env.prod -f docker-compose.prod.yml ps
```

预构建镜像使用 `docker-compose.prebuilt.yml`，其余步骤相同。由于数据库和 Redis 是外部服务，Compose 只会管理 GEOFlow 容器。

## 验证清单

1. `GET /up` 返回 200，网页首页和 `geo_admin` 登录页可访问。
2. `php artisan about` 显示 PostgreSQL/Redis 配置可用（在 app 容器内执行）。
3. `MODELS_BASE_URL` 和 `MODELS_API_KEY` 同时存在；后台 AI 模型测试成功。
4. 在 app 容器执行 `php artisan geoflow:models-internal-check`；需要核对模型目录时追加 `--list`。
5. MCP `initialize`、`tools/list`、`geoflow.catalog` 成功；无 Token 返回 401。
6. queue/scheduler/reverb 容器健康，任务入队后 `task_runs` 有记录，models 用量可见。

## 回滚

```bash
docker compose --env-file .env.prod -f docker-compose.prod.yml down
# 切换到上一版本镜像或 Git revision
docker compose --env-file .env.prod -f docker-compose.prebuilt.yml up -d
```

回滚前保留 `storage/logs`、容器日志和 models 请求 ID。禁止删除集中数据库/Redis 卷；数据库迁移需按对应版本的 Laravel migration 回滚方案单独评估。
