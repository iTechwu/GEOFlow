# CI 机部署运行手册

## 自动化边界

`.github/workflows/ci.yml` 已形成三阶段流水线：

1. `test`：依赖安装、Compose 基础设施边界、部署脚本语法、预构建 Compose 展开、聚焦测试与完整 PHPUnit。
2. `build-images`：测试通过后构建 `linux/amd64` app/web 镜像，只推送当前 Git SHA 的不可变标签。
3. `deploy-production`：在生产自托管 Runner 串行生成 `.env.prod`，执行停机排空发布和全部上线门禁。

`main` 推送自动使用 `upgrade` 模式。首次空库部署必须从已审查的 revision 手动触发 workflow，并选择 `fresh`；不要让程序猜测数据库是否为空。

## Runner 前置条件

- 自托管 Runner 标签包含 `self-hosted`、`linux`、`geoflow-production`。
- Runner 用户可使用 Docker 与 Compose v2，并可写 `GEOFLOW_DEPLOY_DIR`。
- CI 机已加入 `docker-helm.dofe.ai` 提供的外部网络（默认 `common_network`）。
- 外部 PostgreSQL 已启用 pgvector；外部 Redis 已配置鉴权、网络策略和持久化。
- PostgreSQL、Redis、RabbitMQ 均由 `../docker-helm.dofe.ai` 管理，本项目 Compose 不创建这些服务、初始化任务或数据卷。
- GitHub `production` Environment 建议启用审批、分支保护和 Secret 访问限制。

## Repository Variables

必须配置：

| Variable | 示例 |
| --- | --- |
| `GEOFLOW_REGISTRY` | `registry.example.com` |
| `GEOFLOW_REGISTRY_NAMESPACE` | `geo_flow` |
| `GEOFLOW_DEPLOY_DIR` | `/opt/geoflow` |
| `GEOFLOW_APP_URL` | `https://geo.example.com` |
| `GEOFLOW_DB_HOST` / `GEOFLOW_DB_DATABASE` | `postgres.shared` / `geo_flow` |
| `GEOFLOW_REDIS_HOST` | `redis.shared` |
| `MODELS_CHAT_SMOKE_MODEL` | 已启用的 Chat 模型 ID |
| `MODELS_EMBEDDING_SMOKE_MODEL` | 已启用的 Embedding 模型 ID |
| `SSO_API_URL` / `SSO_ISSUER` | SSO 公共 API 与 issuer |
| `SSO_REDIRECT_URI` | `https://geo.example.com/auth/callback` |

按环境覆盖：`GEOFLOW_DB_PORT`、`GEOFLOW_REDIS_PORT`、`MODELS_BASE_URL`、`MODELS_INTERNAL_BASE_URL`、`SSO_INTERNAL_API_URL`、`SSO_DISCOVERY_URL`、`SSO_SERVICE_NAME`、`GEOFLOW_MCP_ENABLED`、`GEOFLOW_MCP_ALLOW_SYSTEM_TOKEN`、`DOCKER_COMMON_NETWORK_NAME`、Web/Reverb 端口和可信代理。

## Secrets

必须配置：

- `GEOFLOW_REGISTRY_USERNAME`、`GEOFLOW_REGISTRY_PASSWORD`
- `GEOFLOW_APP_KEY`、`GEOFLOW_REVERB_APP_SECRET`
- `GEOFLOW_DB_USERNAME`、`GEOFLOW_DB_PASSWORD`、`GEOFLOW_REDIS_PASSWORD`
- `MODELS_API_KEY`、`MODELS_INTERNAL_API_SECRET`
- `SSO_CLIENT_ID`、`SSO_CLIENT_SECRET`
- 允许系统令牌时配置 `GEOFLOW_MCP_TOKEN`；可选配置权限更小的 `GEOFLOW_MCP_READ_TOKEN`
- 禁用系统令牌时，配置短期 `GEOFLOW_MCP_SMOKE_TOKEN` 用于上线验收，不写入 `.env.prod`

`render-prod-env.sh` 先校验所有必填值，再以临时文件原子替换 `.env.prod`，权限固定为 `0600`，不输出 Secret。

## 发布协议

`deploy-prebuilt-release.sh` 拒绝 `latest` 或无标签镜像。升级流程固定为：

```text
pull immutable images
  -> maintenance mode
  -> stop web/workers/reverb
  -> stop app and confirm all old services stopped
  -> one-time drained migration
  -> managed-image readiness
  -> read-only security audit
  -> start all new services
  -> leave maintenance mode
  -> strict production healthcheck
```

最终健康检查失败即发布失败并重新进入维护模式。门禁包含：容器运行状态、`GET /up`、待执行迁移、models 公共 Chat、models 公共 Embedding、models 内部 HMAC、MCP `initialize`、`tools/list` 和只读 `geoflow.catalog`。

首次空库部署：

```bash
GEOFLOW_RELEASE_MODE=fresh GEOFLOW_APP_DIR=/opt/geoflow \
bash /opt/geoflow/deploy-scripts/deploy-prebuilt-release.sh
```

常规升级：

```bash
GEOFLOW_RELEASE_MODE=upgrade GEOFLOW_APP_DIR=/opt/geoflow \
bash /opt/geoflow/deploy-scripts/deploy-prebuilt-release.sh
```

## 回滚与失败处理

- 发布失败保留应用维护模式、日志和持久化 `storage/`，修复原因后重跑同一不可变版本。
- 可将 `.env.prod` 中两个镜像引用切到上一 Git SHA 后重跑发布，但数据库迁移是否支持旧代码必须单独评估。
- 禁止使用 `down -v`，禁止删除集中 PostgreSQL/Redis/RabbitMQ 的容器或卷。
- 保留失败 workflow、容器日志、models 请求 ID 和发布 SHA 作为审计证据。

## 现场验收

代码级门禁不能替代真实环境验收。首次上线后还需确认反向代理 HTTPS/前缀、SSO 回调、队列实际消费、Reverb 连接、models 用量归集和 Redis key 前缀符合生产规划。
