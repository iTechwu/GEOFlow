## 2. 深审发现与修复

| 发现 | 风险 | 完善结果 |
| --- | --- | --- |
| 可信代理允许伪造转发主机影响应用 URL | 链接、重定向和资源地址可能被污染 | 生产环境校验请求有效主机必须匹配 `APP_URL`，`/up` 保持容器健康检查可用 |
| Models Bearer 密钥可随 HTTP 地址发送 | 明文泄漏模型服务密钥 | 公共网关默认强制 HTTPS；同机 HTTP 验收要求专用开关和精确私网 `host:port` 白名单同时存在 |
| Models 探针只判断数组非空 | 无内容 Chat 或无效向量可能误过发布门禁 | 校验非空文本以及非空、有限数值 Embedding 向量 |
| 上游错误正文直接写入命令输出 | CI 日志可能泄漏 Provider 响应字段 | 命令仅输出净化后的状态与失败类别，不回显正文、密钥或上游主机 |
| 外部探针没有瞬态重试 | 连接抖动、429、5xx 会误阻断发布 | 仅对连接异常、429 和 5xx 执行两次受限退避；确定性 4xx 不重试 |
| API v1 没有统一请求频率边界 | 单令牌或单来源可放大资源消耗 | 所有 API v1 路由使用共享限流器，并按 Bearer 摘要和来源 IP 双层分区 |
| npm/Composer 依赖存在已知公告 | 前端与 PHP 供应链风险 | 升级锁文件；npm 和 Composer 安全审计均为 0 个公告 |
| 生产构建在线下载 `latest-stable` Composer | 构建不可复现且增加供应链入口 | 仅使用传入 Composer 镜像中的二进制，生产 vendor 阶段构建通过 |
| 核心后台静态标签仅依赖 `aria-label` | 点击可见标签无法聚焦，语义关联弱 | 文章、分析和 URL 导入的 20 个静态控件改为稳定 `id`/`for`；补齐展开关系和模型测试结果播报 |
| 无障碍扫描器漏查引用和数据行 | 空列表或失效 ARIA 关系可误过 | 增加 AI 模型与文章数据夹具，并检查空/重复 ID、`aria-controls`、`aria-expanded` 和标签文本 |

## 4. 真实环境回归

生产入口使用 `http://127.0.0.1:18080`：

- 正常首页返回 `200`。
- 带伪造 `X-Forwarded-Host` 的首页请求返回 `400`，页面未输出攻击者主机。
- 相同伪造头访问 `/up` 返回 `200`，不会破坏容器健康检查。
- MCP `initialize`、`tools/list` 和 `geoflow.catalog` 全部通过；无令牌请求返回 `401`。
- Google Chrome 隔离环境检查桌面/移动首页与归档共 4 个页面/视口：全部 `200`、每页 1 个 H1、0 横向溢出、0 未命名操作、0 未命名控件、0 console 错误/警告、0 失败请求。
- 本会话没有 Chrome DevTools MCP，浏览器验收使用隔离 Google Chrome 的 Playwright/CDP 完成；没有附着用户日常浏览器配置。

## 5. 当前阻塞与运行态风险

严格发布脚本当前依次通过容器状态、HTTP、数据库和迁移检查，随后在 Models 公共网关处失败。运行容器检查到：

- Models 地址仍缓存为本地 HTTP 服务；
- 精确私网例外仅有 `dofe-models-api-local:3101`；
- `GEOFLOW_MODELS_ALLOW_INSECURE_LOCAL` 在运行态为关闭；
- 工作区 `.env.prod` 又未完整提供公共 Chat/Embedding smoke、内部 HMAC 等门禁输入。

因此安全审计返回 1 个 medium：`OUTBOUND_PRIVATE_TARGETS_CONFIGURED`。该例外与本地 Models 验收目标一致，但必须作为临时配置管理，不能视为零风险。

正式放行前必须完成：

1. 生产优先配置 HTTPS `MODELS_BASE_URL`、服务密钥、Chat smoke 和 Embedding smoke 模型；若确需同机 HTTP，必须同时开启专用本地开关与精确私网白名单。
2. 配置 `MODELS_INTERNAL_BASE_URL` 和内部 HMAC 密钥，执行 `geoflow:models-internal-check`。
3. 更新 `.env.prod` 后清除并重建 Laravel 配置缓存，重启 app、queue、scheduler、reverb，确认文件配置与所有进程运行态一致。
4. 重新执行 `deploy-scripts/geoflow-healthcheck.sh`，要求 Models 公共、内部与 MCP 三组门禁全部通过。
5. 使用正式域名和有效生产 SSO 管理员完成后台弹窗键盘焦点、Escape 关闭、焦点恢复和完整管理业务浏览器回归。
